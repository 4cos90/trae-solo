# 几何冲刺 - 技术架构文档

## 1. 架构设计

```
┌─────────────────────────────────┐
│          index.html             │
│  ┌───────────────────────────┐  │
│  │       Canvas 画布          │  │
│  │  ┌─────────────────────┐  │  │
│  │  │    游戏渲染层        │  │  │
│  │  │  - 背景层           │  │  │
│  │  │  - 轨道层           │  │  │
│  │  │  - 实体层           │  │  │
│  │  │  - UI层             │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │       游戏状态机          │  │
│  │  IDLE → COUNTDOWN →      │  │
│  │  PLAYING → GAMEOVER       │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

## 2. 技术选型

- **渲染引擎**：原生 HTML5 Canvas（零依赖）
- **动画循环**：requestAnimationFrame
- **状态管理**：原生 JavaScript 类
- **本地存储**：localStorage（最高分记录）
- **部署方式**：GitHub Pages（静态文件托管）

## 3. 游戏状态机

| 状态 | 描述 | 可执行操作 |
|------|------|-----------|
| IDLE | 开始界面 | 点击/按键开始 |
| COUNTDOWN | 倒计时3秒 | 等待倒计时结束 |
| PLAYING | 游戏进行中 | 左右移动躲避 |
| GAMEOVER | 游戏结束 | 查看分数，点击重玩 |

## 4. 核心类设计

### Game 类
- `init()`: 初始化画布和事件监听
- `start()`: 开始新游戏
- `update(deltaTime)`: 更新游戏逻辑
- `render()`: 渲染画面
- `gameOver()`: 结束游戏

### Player 类
- `x, y`: 位置坐标
- `lane`: 当前所在轨道（0-2）
- `moveTo(lane)`: 移动到指定轨道

### ObstacleManager 类
- `obstacles[]`: 障碍物数组
- `spawn()`: 生成新障碍
- `update()`: 更新障碍位置
- `checkCollision(player)`: 碰撞检测

### PowerUp 类
- `powerups[]`: 能量球数组
- `spawn()`: 生成能量球
- `collect()`: 收集检测

## 5. 输入处理

| 平台 | 操作 | 按键/区域 |
|------|------|----------|
| 桌面 | 左移 | ← 或 A |
| 桌面 | 右移 | → 或 D |
| 移动端 | 左移 | 屏幕左半边点击 |
| 移动端 | 右移 | 屏幕右半边点击 |

## 6. 性能优化

- 对象池复用障碍物和能量球实例
- 离屏对象及时销毁
- 使用 `will-change: transform` 优化渲染
- 限制同时存在的障碍物数量 ≤ 10
